# System-ESG V4.1.11 Technical Acceptance

Date: 2026-10-16 (Asia/Shanghai)

Decision: **Technical acceptance candidate.** The controlled human pilot is retained as an optional product-learning activity and is no longer a release gate for this version.

## Fixed in this release

- Browser-exported pilot timing headers are mapped to the analyzer's canonical timing fields.
- `record_status`, `validation_errors`, and `exported_at` survive collection and remain auditable.
- Every asynchronous progress and draft operation is bound to the user who started it.
- Account changes invalidate pending sync work before the new session is applied.
- The existing deletion generation protection remains active.

## Acceptance boundary

Technical acceptance covers automated checks, browser behavior, data contracts, account isolation, persistence, and regression evidence. It does not claim usability, learning effectiveness, SUS, or market fitness without real participants.

The optional pilot remains available for later rolling improvement. Pilot results may create new product work, but the absence of pilot results does not block this release.

## Verification result

- Static, contract, analyzer, and account-isolation checks: 171 passed.
- Edge desktop and 390 px browser suites passed for Gate 2 and Gate 3.
- Optional pilot browser flow: 11/11 passed.
- Browser export to merge and analysis contract: 3/3 passed.
- Browser console errors and warnings: 0; unhandled HTTP 4xx/5xx: 0.

## Remaining product improvements

- Run the optional pilot when target users are available and treat its results as a new improvement backlog.
- Continue growing the approved question bank; unavailable exam sizes remain correctly disabled until enough approved questions exist.
- Add a live two-account browser regression to staging CI when dedicated disposable credentials are available. The local module-level account isolation regression is included now.
