# System-ESG V4.1.7 Gate 3 使用者試點操作手冊

版本：V4.1.7 Gate 3 Revalidation Candidate
用途：10–20 名目標使用者的真人試點；自動測試不得代替本試點。

## 1. 樣本與分組

- 招募 10–20 人；至少 5 名 ESG 初學者、至少 5 名 ESG／永續／碳管理實務人員。
- 每位參與者使用匿名編號 `P01`–`P20`，不得在原始表記錄姓名、電話或私人信箱。
- 桌面與手機均須涵蓋；記錄裝置、作業系統、瀏覽器及版本。
- 主持人只在參與者明確求助後提示，並將每次求助記入 `help_count`。

## 2. 測試前準備

1. 為每位參與者建立獨立 staging 帳號。
2. 確認 staging 網址、Supabase 專案及正式站完全隔離。
3. 清除該帳號既有 staging 進度。
4. 準備計時器、任務單、前後測與 SUS 問卷。
5. 取得參與者同意；告知只收集產品驗證資料且可隨時停止。

## 3. 主持人逐字腳本

> 今天測試的是產品，不是測試你。請依任務單自行操作，過程中可說出你在找什麼、預期什麼。遇到阻礙時先自行處理；需要協助時請明確提出。系統錯誤、資料遺失或無法繼續都會記錄，但不會影響對你的評價。

## 4. 使用者任務單

每項任務分別記錄成功／失敗、開始時間、結束時間、操作錯誤及求助次數。

| 任務 | 完成條件 |
|---|---|
| T1 登入 | 使用指定 staging 帳號登入並看到學習總覽 |
| T2 指定學習 | 開啟指定模組、展開知識點並標記完成 |
| T3 情境練習 | 完成至少 3 道核准題，包含一題情境題 |
| T4 建立錯題 | 故意答錯主持人指定題目，錯題數增加 |
| T5 錯題回補 | 進入「錯題回補」，重答正確後錯題數減少 |
| T6 學習報告 | 開啟學習報告並說出一個可見的學習指標 |
| T7 續接 | 重載或登出再登入，確認 T2–T6 的進度仍存在 |
| T8 雲端同步 | 已同意同步者於另一裝置登入，確認進度一致 |

任務成功定義：參與者未由主持人代為操作，且最後狀態符合完成條件。求助不必然判定失敗，但須記錄。

## 5. 前測、學習與後測

- 使用 `GATE3-PILOT-ASSESSMENT.md` 的固定核准題組。
- 前測在指定學習前完成；不得顯示解析。
- 完成 T2–T6 後進行後測；題序與選項順序重新排列。
- 前後測均換算為 0–100 分；`improvement_pp = post_score - pre_score`。
- 同題重測會產生記憶效應，報告中必須列為限制，不得把結果宣稱為長期能力提升。

## 6. SUS 易用性問卷

完成所有任務後，以 1（非常不同意）至 5（非常同意）回答：

1. 我願意經常使用這個系統。
2. 我覺得這個系統不必要地複雜。
3. 我覺得這個系統容易使用。
4. 我需要技術人員協助才能使用這個系統。
5. 我覺得各項功能整合良好。
6. 我覺得系統有太多不一致之處。
7. 我認為大多數人能很快學會使用。
8. 我覺得系統操作很笨重。
9. 我使用這個系統時感到有信心。
10. 我需要先學很多東西才能開始使用。

計分：奇數題減 1；偶數題以 5 減原分；十題加總後乘 2.5，得到 0–100 分。

## 7. 訪談問題

1. 哪一步最清楚？哪一步最困難？
2. 「錯題回補」這個名稱是否符合你的預期？
3. 你是否相信題目來源與解析？還缺少什麼證據？
4. 你在工作中最需要哪一類 ESG 情境？
5. 什麼條件會讓你願意再次使用或推薦給公司？

## 8. 原始資料與判定

- 每位參與者開始第一項任務時，將 `pilot_started` 填為 `yes`，並完成 `data/gate3-pilot-raw.csv` 對應的一列。
- 不得刪除失敗樣本；未完成欄位留空並在 `notes` 說明。
- 已開始試點的參與者一律納入核心任務完成率分母；中途退出、漏填任務或問卷不會被分析器排除。
- 執行 `python tools/analyze_gate3_pilot.py data/gate3-pilot-raw.csv --output test-results/gate3-pilot-summary.json`。
- Gate 3 建議門檻：核心任務完成率 ≥95%、資料遺失 0、不可恢復中斷 0、平均提升 ≥15 個百分點、平均 SUS ≥70、P0=0、P1=0。
- 少於 10 位參與者、任何已開始者紀錄不完整，或兩個目標分組未同時具備完整紀錄時，分析工具必定輸出 `HOLD`。
